# CLIの操作設計

Hibanaの基本操作は、アプリを作る`init`、手元で動かす`dev`、配備する`deploy`です。利用者が達成したい操作を入口にし、そのために必須の準備はCLIが行います。

```bash
hibana init my-api
cd my-api
npm run dev
# 配備先へログインした後
npm run deploy
```

## 必須の準備は自動化する

`init`はHonoを既定にしてnpm依存を導入します。`dev`はCLIと同じバージョンのPC用ランタイムを必要なときに取得し、SHA-256を検証して保存します。準備済みのランタイムは再利用します。初回起動のための追加コマンドや確認入力は必要ありません。

ランタイムの自動取得を拒否するフラグや環境変数は提供しません。閉域環境には`runtime install --from FILE --sha256 HASH`による事前搬入、手元の実行ファイルには`--runtime PATH`や`HIBANA_RUNTIME_BIN`で対応します。これらは実際に使用するランタイムを選ぶ機能です。準備済みなら通常の`dev`がそのまま使えます。

## 必要な場所で詳しく説明する

`hibana`と`hibana --help`は最初の実行例と目的別のコマンド一覧を表示します。管理者向けのKubernetes設定やランタイムの搬入手順は、各コマンドのヘルプで説明します。

```bash
hibana dev --help
hibana help deploy
hibana secret put --help
hibana platform install --help
```

ヘルプはプロジェクト、認証情報、外部接続がなくても表示できます。`init`完了後は次に実行するコマンドを表示します。依存導入に失敗したときもプロジェクトを残し、`npm install`から再開する手順を案内します。

## 入力を無視しない

コマンドに使えないオプションや余分な引数は、設定ファイルの読み込みや外部操作より前に検出します。たとえば未対応の`deploy --dry-run`を無視して本番配備することはありません。コマンドやオプションの打ち間違いには修正候補を表示し、推測した操作を自動実行しません。

通常の入力エラーは標準エラー出力に理由と修正方法を表示し、終了コード1を返します。ヘルプは標準出力に表示し、終了コード0を返します。JSON構文エラーにはファイルの場所を示し、設定値をエラー表示へコピーしません。既存の`list`や`secret list`のJSON出力はスクリプトから利用できます。

## 選択には目的を持たせる

`--port`は待受ポート、`--profile`は接続先、`--template`はアプリの言語・書き方を選びます。`--no-watch`は一度ビルドして起動する用途、`init --no-install`は雛形だけを生成する用途に使います。必須の内部準備を行うかどうかは利用者に選ばせません。

削除の確認、`--yes`によるスクリプト実行、管理対象のKubernetes資格情報は引き続き明示します。これらは実行先や既存データへの操作を決めるものです。

基本方針の参考は[Command Line Interface Guidelines](https://clig.dev/)の、目的に沿った既定動作、段階的なヘルプ、修正可能なエラー、シェルでの組み合わせに関する指針です。
